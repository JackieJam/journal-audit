# 跨年检测阈值参数化 —— 去耦版方案三实施计划

> 目标：让 `cross_year_accrual` / `cross_year_revenue` 的 config 参数真正驱动跨年检测，
> 给审计师"调阈值真生效"的灵活性，同时避开反馈环、缓存陷阱和可复现性风险。
> 本文档供 review，**通过后再动代码**。

## 1. 问题陈述

当前 `default_rules.json` 把以下参数暴露为可调，并由 `rule_text.py` 渲染到 UI 上给用户看：

| Rule key | 参数 | 默认值 | UI 文案（rule_text.py） |
|---|---|---|---|
| `cross_year_accrual` | `coverage_threshold` | 0.8 | "冲回覆盖率若低于 80%……" |
| `cross_year_accrual` | `match_window_days` | 90 | "在 90 天内……"（实际用 Q1 写死） |
| `cross_year_revenue` | `dec_multiplier` | 1.8 | "12 月收入高于前 11 月均值 1.8 倍……" |

但真正执行检测的 `modules/cross_year.py` 把阈值**硬编码**了：

- `cross_year.py:120` → `if coverage < 0.80`
- `cross_year.py:178` → `if ratio_n > 1.8`

后果：用户在界面把 80% 改成 70%，**检测行为完全不变且无任何提示**。这同时违反
`CLAUDE.md` 的铁律「不在代码里硬编码任何阈值（全部从 rules_config 读）」。

## 2. 设计原则（去耦的四个决策）

1. **单一来源**：阈值从 `rules_config` 读，默认值来自 `default_rules.json`。代码里不再有
   `0.80` / `1.8` 字面量。
2. **斩断反馈环**：跨年发现会作为输入喂给 LLM 校准（`generate_rules_config`）。因此
   **禁止 LLM 改写 `cross_year_*` 的检测阈值**——这两个参数只由用户/默认值控制。这样
   "阈值→发现→校准→阈值" 的循环被打断，结果不再依赖操作顺序。
3. **缓存键完备**：阈值必须进 `@st.cache_data` 的键，且只传标量（沿用现有
   `_overrides_signature` 的做法），避免传整个 cfg dict 导致哈希不稳或静默用旧缓存。
4. **审计留痕**：把实际生效的阈值快照进每个 `CrossYearFinding.evidence`，底稿可追溯
   "这批样本按什么阈值抽出"。

## 3. 范围界定

**第一阶段只做已有 config 项的参数**（2 个函数、3 个参数）：
- `_accrual_reversal_pairs` → `coverage_threshold`、`match_window_days`
- `_revenue_timing_drift` → `dec_multiplier`

**明确不在第一阶段范围内**（避免"半吊子可调"误导用户）：
- 另外 5 个跨年函数（资金归集、循环交易、费用突增、手工凭证趋势、科目关系漂移）无 config 项，保持现状。
- 次级硬编码常量：`10_000`（计提金额下限）、`1_000_000`（高危分级线）、`0.05`（金额不符容差）、Q1 月份范围等。
- 这些在 UI 上要么不展示、要么标注「按默认值计算」，第二阶段再评估是否参数化。

## 4. 分阶段实施步骤

### 阶段 0：先补测试（红 → 绿基线）

**在改任何生产代码前**，给 `tests/test_cross_year.py` 增加锁定测试：

- `test_accrual_coverage_threshold_respected`：构造一组「冲回覆盖率 75%」的两年数据，
  - 阈值 0.80 时应产生「悬空预提」发现；
  - 阈值 0.70 时不应产生。
  当前硬编码下第二个断言会失败 —— 这正是要修的行为，作为 TDD 红灯。
- `test_revenue_multiplier_threshold_respected`：类似，构造 12 月收入为均值 1.6 倍的数据，
  验证 1.8 阈值不触发、1.5 阈值触发。
- `test_cross_year_cache_invalidates_on_threshold_change`：同一 `year_map`，先后用不同阈值
  调用，断言结果不同（证明缓存键生效，不是返回旧缓存）。

> 这一步先写、允许失败，作为后续改造的验收标准。

### 阶段 1：阈值读取层（不碰缓存/调用方）

1. 在 `cross_year.py` 新增一个**纯函数**抽取阈值，集中默认值，避免散落：
   ```python
   def _cross_year_thresholds(cfg: dict | None) -> dict:
       cfg = cfg or {}
       accrual = cfg.get("cross_year_accrual", {})
       revenue = cfg.get("cross_year_revenue", {})
       return {
           "coverage_threshold": float(accrual.get("coverage_threshold", 0.80)),
           "match_window_days": int(accrual.get("match_window_days", 90)),
           "dec_multiplier": float(revenue.get("dec_multiplier", 1.8)),
       }
   ```
   默认值与 `default_rules.json` 保持一致（单一来源仍是 json，这里只是兜底）。
2. 把 `_accrual_reversal_pairs` / `_revenue_timing_drift` 改为接收阈值参数，替换
   `0.80` / `1.8` 字面量。

### 阶段 2：缓存键 + 调用链

3. 改 `_run_cross_year_cached` 签名，新增 `thresholds_key: tuple` 进缓存键
   （把上面 dict 排序成稳定元组，**只放标量**）。
4. 改 `run_cross_year_analysis(year_map, cfg=None)`：
   - 计算 `thresholds = _cross_year_thresholds(cfg)`；
   - 把 `thresholds` 的标量元组作为缓存键的一部分传入。
5. 改调用方 `components/tabs/analysis/tab.py:72`：
   `run_cross_year_analysis(st.session_state.year_map, st.session_state.rules_config)`。
   （`rules_config` 在 session 初始化时即为默认值，恒可用。）

### 阶段 3：重算时机 + 留痕

6. **失效触发**：在 `rules.py` 中用户编辑/保存 `cross_year_accrual` 或
   `cross_year_revenue` 参数的代码路径里，清空 `st.session_state.cross_year_findings`
   （置空即可，下次进 Tab1 守卫 `not cross_year_findings` 会重算）。
   - 需定位 rules.py 中这两个 rule 的参数写回点，加一个"关键参数变更→失效跨年缓存"的钩子。
7. **审计留痕**：在两个函数产出的 `CrossYearFinding.evidence` 里加
   `"threshold_used": <实际阈值>`，并让 `rule_text.py` 的展示文案从同一来源取值
   （消除"显示 80% 实际 70%"的二次脱节）。

### 阶段 4：斩断 LLM 反馈环

8. 在 `rule_generator.py` 的 schema/后处理里，明确**剔除或忽略** LLM 对
   `cross_year_accrual.coverage_threshold`、`cross_year_revenue.dec_multiplier` 的改写
   （保留 `enabled` / `rationale`，但检测阈值以用户/默认为准）。
   - 实现方式二选一：(a) prompt 里说明这两项不可由模型设定；(b) 后处理用默认/现值覆盖模型返回值。
   - 推荐 (b)，更稳，不依赖模型遵从 prompt。

### 阶段 5：回归 + 文档

9. 跑阶段 0 的新测试（现在应全绿）+ 全量 `pytest`。
10. 更新 `CLAUDE.md` 里 `cross_year.py` 的说明，注明阈值已 config 化、且不参与 LLM 校准。

## 5. 风险 → 缓解映射

| 风险 | 等级 | 缓解（对应步骤） |
|---|---|---|
| A. 缓存不失效→静默用旧发现 | 高 | 阈值进缓存键、只传标量（步骤 3-4）；阶段 0 缓存失效测试兜底 |
| B. 与 LLM 校准形成反馈环 | 中高 | 禁止 LLM 写检测阈值（步骤 8） |
| C. Tab2 改参数 Tab1 不重算 | 中 | 参数变更清空 findings（步骤 6） |
| D. 可复现性/底稿口径 | 中 | 阈值快照进 evidence（步骤 7） |
| E. 7 函数仅 2 个可调，半吊子 | 中低 | 明确范围 + UI 标注（第 3 节）；5 个留第二阶段 |
| F. 测试缺口→静默回归 | 中 | 先补测试再改（阶段 0） |
