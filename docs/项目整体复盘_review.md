### 跨年阈值参数化（本轮重点工程）

把 7 个跨年检测函数中**全部硬编码阈值**收敛到 `rules_config`（UI 两项 +
`cross_year_detection` 高级块），默认值与历史一致（零行为变更），并系统性解决了
四类风险：阈值进缓存键（改了真失效）、参数变更清 findings（重算时机）、

这同时使项目符合自身 CLAUDE.md「不在代码里硬编码任何阈值」的铁律。

## 三、架构评估

**优点（保持）**

- 分层清晰：`modules/`（领域逻辑）/ `components/`（UI 与渲染）/ `config/`（常量）
  职责分明；`knowledge_base.py` 单点负责持久化，其他模块不碰 `~/.audit_tool/`。
- 可审计性内建：规则带 `rationale`、阈值带 `threshold_used` 留痕、JSON 损坏隔离备份。
- 缓存键设计严谨：`@st.cache_data` 键包含分类覆盖签名 + 阈值签名，避免静默用旧结果。
- 测试驱动：232 个测试覆盖核心路径，重构有护栏。

**可改进（非紧急）**

- **大文件**：`charts.py`(1359)、`rule_engine.py`(1260)、`llm_orchestration.py`(1039)
  仍超 800 行。属可维护性问题，非正确性问题（详见第五节，本轮刻意未拆）。
- **LLM 调用层**：`verify_with_llm` 与 `llm_client.chat_with_retry` 重试语义不同
  （前者对任意异常重试），目前刻意保留差异。若未来统一重试策略，可评估合并。

## 五、遗留事项与本轮的取舍（重要）

以下几项**经评估后刻意未做**，并非遗漏，理由如下：

1. **大文件拆分（#3/#4）**：纯结构整洁度，零功能收益，且 re-export 断裂是隐性运行期
   风险（冒烟测试不渲染每一张图/每一条规则路径，断裂可能漏网）。建议作为**独立的、
   可单独验证的重构**推进：改造为包 + `__init__` 完整再导出，逐个 sub-tab 手测覆盖。
2. **分类/状态常量 enum 化（#17/#18）**：原型验证发现，enum 成员存入 DataFrame 后
   `astype(str)` 会变成 `<Category.X: '…'>` 的 repr，**破坏** `balance_sheet` 等
   依赖 `astype(str)` 的路径；且正解 `StrEnum` 为 3.11+，无法在当前环境验证。
   现有命名字符串常量已分组（`ALL_CATEGORIES`），enum 的边际收益不抵其风险。
3. **`socksio` / `xlsxwriter` 依赖（#38/#39）**：核实均为运行期实际依赖
   （SOCKS 代理 / Excel 导出引擎），保留。
4. **跨年第二阶段的 `match_window_days` 语义对齐**：当前代码用「次年 Q1」近似，
   与参数名不完全一致。已留作显式待办（见实施计划文档第 8 节）。

这些取舍体现一条原则：**对一个正在使用的审计工具，不为满足风格指标而做高风险的
零收益改动。**

## 六、前瞻建议（按优先级）

1. **纳入 CI**：`ruff check` + `pytest` 作为 PR 门禁；`mypy` 从 `modules/` 渐进开启。
2. **修复 flaky 测试**：让 230+ 测试 100% 确定性通过，保护后续重构。
3. **若要拆大文件**：按"包 + 再导出 + 每条 UI 路径手测"的方式单独成一个 PR。
4. **跨年第二阶段语义对齐**：把 `match_window_days` 真正接进预提配对窗口。
5. **LLM 层**：评估是否统一 `verify_with_llm` 的重试语义到 `chat_with_retry`。
